# ADR-0012：官方帳號以 App 產生的一次性綁定碼綁定帳號

- 狀態：已接受
- 日期：2026-11-13
- 相關：ADR-0011、ADR-0023、ADR-0024

## 背景

用戶在 LINE 官方帳號（OA）跟 agent 說話時，webhook 只帶 LINE 的 userId。系統需要知道這個 LINE 用戶對應到哪個 App 帳號（Google 登入，見 ADR-0023），才能讓 agent 存取正確的 task、行程與記憶。

綁定錯誤的後果嚴重：綁錯人等於把一個用戶的資料交給另一個人。

## 考慮過的選項

1. **App 產生一次性綁定碼**：App 內產生短效代碼，用戶把它傳給 OA 完成綁定。不需要額外網頁與 LINE Login channel。
2. **LINE 官方 Account Link**：OA 發 linkToken，用戶在我們的網頁登入後帶 nonce 轉回 LINE。是平台標準做法，但要多做一個網頁登入頁。
3. **App 內加 LINE Login**：同一個 provider 下 userId 相同，體驗最順，但 App 會有兩種「登入 LINE」，容易與連結個人帳號混淆。

## 決定

採用選項 1。

- 用戶在 App（已登入狀態）按「連結官方帳號」，後端產生一組一次性綁定碼並記錄它屬於哪個 App 帳號。
- 綁定碼的要求：密碼學安全的隨機值、足夠長到無法猜測、有效期 10 分鐘、只能使用一次。資料庫只存雜湊值。
- App 用 LINE 的 URL scheme 開啟 OA 聊天室並自動帶入含綁定碼的訊息，用戶按送出即可，不需要手動輸入。
- OA webhook 收到符合格式的綁定碼訊息時：驗證雜湊、有效期、未使用，通過後把該 LINE userId 綁定到對應的 App 帳號，並用 reply 回覆綁定成功。
- 一個 LINE userId 只能綁定一個 App 帳號，一個 App 帳號只能綁定一個 LINE userId。重新綁定會取代舊的綁定。
- WhatsApp 官方帳號沿用同一套綁定碼機制，與 LINE 的綁定可以同時存在；差異（預填連結、以 business-scoped user ID 為主鍵）見 ADR-0024。
- 未綁定的 LINE 用戶傳任何其他訊息，只會收到「請先在 App 內連結官方帳號」的回覆，不會觸發 agent。
- 用戶可以在 App 解除綁定。刪除帳號時一併解除（見 ADR-0022）。
- webhook 一律驗證 LINE 的簽章（`x-line-signature`）後才處理。
- 綁定碼的驗證失敗次數做限流，避免暴力嘗試。

## 後果

### 正面

- 實作最少：不需要額外的網頁登入頁，也不需要 LINE Login channel。
- 綁定由已登入的 App 發起，綁定碼證明「送出訊息的 LINE 用戶」與「App 登入者」是同一個人操作。

### 負面與接受的風險

- 綁定碼會以明文出現在用戶與 OA 的聊天紀錄中。它是一次性且短效的，使用後即失效，但流程上要確保過期與已使用的碼絕對不能再被接受。
- 用戶若把含綁定碼的訊息轉給別人，在有效期內對方可以把自己的 LINE 綁到該用戶的 App 帳號。短效期與一次性降低但不消除這個風險；綁定成功時應在 App 內顯示通知，讓用戶發現異常綁定。
- 讀取服務若沒有略過本產品 OA 的對話（見 ADR-0003），綁定碼會被當成一般訊息保存。
- LINE 開啟 OA 並帶入預填訊息的 URL scheme 行為需要在 iOS 與 Android 實測。
