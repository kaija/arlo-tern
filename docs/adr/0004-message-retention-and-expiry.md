# ADR-0004：原始訊息保存期與到期處理

- 狀態：已接受
- 日期：2026-11-13
- 相關：ADR-0005、ADR-0008、ADR-0014、ADR-0015、ADR-0022

## 背景

系統保存原始訊息，目的是讓 agent 可以查詢歷史對話（見 ADR-0015）。原始訊息含有第三方內容，保存越久風險越高。產品已決定用戶可以設定最長保存時間，預設三個月。

原始訊息到期後，從它衍生出來的資料（task、詐騙警告紀錄、agent 記憶）要怎麼處理，需要另外決定。

## 考慮過的選項

1. **只刪原文，衍生資料保留**：衍生資料只存 AI 整理過的欄位，不存原文引用。
2. **衍生資料保留原文片段**：用戶永遠看得到依據，但等於延長了第三方內容的保存期。
3. **衍生資料一併刪除**：資料最小化最徹底，但行事曆歷史與已完成事項會消失。

## 決定

採用選項 1。

- 保存期由用戶設定，選項為 7 天、30 天、90 天，預設 90 天，上限 90 天（選項的具體數值是預設假設）。
- 每天執行一次清除工作，硬刪除超過保存期的原始訊息。保存期以訊息的收到時間起算。
- 用戶縮短保存期時，下一次清除工作就套用新的期限。
- task、行程、詐騙警告紀錄、agent 記憶屬於用戶自己的資料，不隨原始訊息到期而刪除。
- 衍生資料只存 AI 整理過的欄位（標題、時間、分類、手法類型、信心分數），**不複製原文片段**。
- 衍生資料可以帶一個指向來源訊息的參照，供用戶在保存期內回頭看依據。來源訊息刪除後，參照變成空值，App 顯示「來源訊息已過期」。
- 用戶刪除帳號或中斷 LINE 連結時的刪除行為見 ADR-0022。

## 後果

### 正面

- 第三方內容的保存期有明確上限，而且用戶可以縮短。
- 行事曆歷史不會因為訊息到期而消失。

### 負面與接受的風險

- 原始訊息到期後，用戶無法回頭確認 task 或警告是從哪句話來的。
- AI 整理的標題與摘要仍可能帶有第三方資訊（例如「跟小明吃飯」），這部分會長期保留。
- 資料庫只用磁碟加密（見 ADR-0005），已刪除的訊息在備份過期前仍存在於備份中。備份的保存期應該短於或等於訊息保存期的合理範圍，並寫進隱私政策。
- agent 對話紀錄的保存期沒有在這次對齊中決定，見 ADR-0014 的待決事項。
