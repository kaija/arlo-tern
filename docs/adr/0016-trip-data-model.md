# ADR-0016：旅遊行程採用獨立的 Trip 結構

- 狀態：已接受
- 日期：2026-11-13
- 相關：ADR-0008、ADR-0010、ADR-0013、ADR-0017

## 背景

一般 task 只需要日期與時間。旅遊需要詳細的每日、每小時規劃，而且用戶要能用 AI 查詢與安排行程。需要決定旅遊行程的資料模型，以及它與 task、行事曆的關係。

## 考慮過的選項

1. **獨立的 Trip 結構**：Trip 底下是逐日的行程項目，有自己的欄位與工具。
2. **沿用 task 加父子關係**：只有一種資料表，但 task 沒有結束時間、地點、順序這些欄位，要把 task 表加胖，而且幾十個子 task 會各自觸發到期提醒。
3. **行程存成一份文件**（JSON 或 Markdown）：最快做出來，但無法在日檢視跟其他 task 並排，用戶手動改單一項目困難，agent 改一項就要重生整份。

## 決定

採用選項 1。

### 資料模型

- **Trip**：名稱、目的地、開始與結束日期、時區、狀態（規劃中、已確認、已結束、已取消）、備註。
- **行程項目**（屬於某個 Trip 的某一天）：
  - 開始時間與結束時間；
  - 類型（景點、餐飲、交通、住宿、其他）；
  - 標題與備註；
  - 地點：名稱、地址、座標、地點 ID（見 ADR-0017），可為空；
  - 交通類項目：出發地、目的地、交通方式、預估時間；
  - 當日內的排序。
- 行程項目的時間以 Trip 的時區解讀與顯示。出國行程在行事曆上同時標示當地時間。
- Trip 與 task 是不同的實體。Trip 可以關聯若干一般 task（例如「訂機票」「換日幣」），這些 task 走原本的 task 流程。

### 行事曆顯示

- 月檢視與週檢視：Trip 顯示成跨日區塊。
- 日檢視：該日的行程項目與一般 task 依時間並排顯示。
- 點進 Trip 可以看到完整的逐日行程。

### 編輯

- agent 有專屬工具（見 ADR-0013）：建立 Trip、新增與修改與刪除行程項目、移動項目到其他日期或時間、重排當日順序、查詢 Trip。agent 以項目為單位修改，不重寫整份行程。
- 用戶可以在 App 手動新增、修改、刪除、拖移行程項目。
- agent 對行程的修改留下變更紀錄，可還原，與 task 一致（見 ADR-0008）。

### 來源

- Trip 由用戶在 App 建立，或在與 agent 的對話中建立。
- 訊息管線從對話中偵測到旅遊相關內容時，只產生一般 task（例如「10/3 去東京」），不自動建立 Trip 與行程項目。

## 後果

### 正面

- 結構清楚，能表達時區、地點、項目之間的交通時間。
- 行程項目與一般 task 可以在日檢視並排。
- agent 可以做小幅修改，不必重生整份行程。

### 負面與接受的風險

- 多一組資料表、API 與工具，行事曆要處理兩種實體。
- 行程項目之間的時間衝突與交通時間是否足夠，沒有由資料模型強制，靠 agent 規劃時檢查；用戶手動修改後可能產生衝突，App 只做提示。
- 跨時區的 Trip（例如中途轉機）只有一個時區欄位，無法精確表達；MVP 接受這個限制。

## 待決事項

- 行程項目的提醒規則沒有在這次對齊中決定。暫定：MVP 不對每個行程項目逐一提醒，只對 Trip 的開始發一次提醒（依 ADR-0010 的規則）；是否加入「下一個行程」提醒，內測後再決定。
- Trip 是否可以分享給同行者，不在 MVP 範圍。
