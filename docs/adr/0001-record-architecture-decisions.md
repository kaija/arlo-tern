# 0001. 以 ADR 記錄架構決策

- 狀態：已接受
- 日期：2026-11-07

## 背景與問題

本專案包含 React Native App 與多個 backend 服務，且會整合多個第三方平台（Google、LINE、WhatsApp、LLM）。需要一個可追蹤「為什麼這樣決定」的方式，讓決策可以被引用、修訂與取代。

## 考慮的選項

1. 每個決策一個檔案，放在 `docs/adr/`
2. 所有決策寫在同一份文件

## 決策

採用選項 1：

- 位置：`docs/adr/`
- 格式：MADR 風格（見 [template.md](template.md)），繁體中文撰寫
- 檔名：`NNNN-短標題.md`，編號遞增，不重複使用
- 索引：[README.md](README.md)，依主題分類，並列出尚未決定的事項
- 只記錄已確認的決策；尚未確認的事項列在該 ADR 的「待決」或 README 的「待決事項」，不寫成決策

## 後果

### 正面

- 每個決策可獨立被取代（狀態改為「被 NNNN 取代」），歷史可追蹤
- 新成員可從索引快速掌握系統全貌

### 負面 / 風險

- 需要紀律：決策變更時必須新增或更新 ADR
