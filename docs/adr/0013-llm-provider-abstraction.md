# 0013. LLM 透過供應商抽象層使用，可替換

- 狀態：已接受
- 日期：2026-11-07

## 背景與問題

系統有多種 LLM 工作，需求各不相同：

- 個人 AI agent 對話（含工具呼叫：查詢行程、安排 task）
- 從訊息 / 郵件中抽取 task
- 可疑訊息偵測
- 依緊急度決定提醒時間

不同工作在品質、延遲、成本上的取捨不同，市場上的模型也持續變動。

## 考慮的選項

1. 綁定 Anthropic Claude
2. 綁定 OpenAI
3. 建立供應商抽象層，依任務選擇模型

## 決策

- 業務程式碼只依賴系統內部定義的 LLM 介面，不直接呼叫任何供應商的 SDK
- 每種任務（agent 對話、task 抽取、可疑偵測、提醒決策）可以各自設定使用的供應商與模型
- 各供應商以 adapter 實作該介面

## 後果

### 正面

- 可依任務在品質與成本之間取捨，更換模型不必改業務程式碼
- 某家供應商故障或漲價時，有替代方案

### 負面 / 風險

- 抽象層要能涵蓋工具呼叫、串流、結構化輸出等能力，各家的差異會讓抽象層變複雜
- 換模型後，prompt 與輸出品質要重新驗證

## 待決

- 各任務的預設供應商與模型
- 是否採用現成的多供應商 SDK，或自行實作 adapter
- 送給 LLM 供應商的資料處理條款（訊息內容很敏感）
