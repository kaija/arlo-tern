# 0013. LLM 透過自有抽象層使用，候選模型由評測決定

- 狀態：已接受
- 日期：2026-11-07（2026-11-11 更新）

## 背景與問題

系統有多種 LLM 工作，需求各不相同：

- 個人 AI agent 對話：多步工具呼叫（旅遊規劃、查詢並更新 todo / schedule、引用記憶）
- 從訊息 / 郵件中抽取 task
- 可疑訊息判斷
- 依緊急度設定提醒時間

不同工作在品質、延遲、成本上的取捨不同，市場上的模型也持續變動。送給 LLM 的內容包含用戶的 email 與聊天內容，屬於敏感資料。

## 考慮的選項

供應商策略：

1. 綁定 Anthropic Claude
2. 綁定 OpenAI
3. 建立供應商抽象層，依任務選擇模型

抽象層實作：

1. 自有介面 + 各供應商官方 SDK
2. Vercel AI SDK
3. LangChain.js

## 決策

- **自有介面 + 官方 SDK**：業務程式碼只依賴系統內部定義的 LLM 介面。每家供應商以其官方 SDK 實作 adapter（例如 Anthropic 用 `@anthropic-ai/sdk`），不使用第三方的多供應商抽象
- **每種任務各自設定**供應商與模型
- **候選模型**：

  | 任務 | 候選 |
  | --- | --- |
  | 對話型 agent | Claude Opus 5.5（`claude-opus-5-5`）、OpenAI GPT-6.1 Sol、Gemini 4 Argon |
  | task 抽取、可疑判斷、設定提醒 | Claude Sonnet 5.5（`claude-sonnet-5-5`）、OpenAI Terra 6.1、Gemini 3.8 Flash |

- **預設模型由評測決定**：每個任務用同一份評測資料比較候選的品質與成本，再決定預設。沒被選為預設的候選可以作為備援
- **資料處理條件**：只使用不以客戶資料訓練模型的商用 API 條款，並與每家供應商簽署 DPA（見 [0024](0024-privacy-consent-compliance.md)）

## 後果

### 正面

- 可依任務在品質與成本之間取捨，更換模型不必改業務程式碼
- 某家供應商故障或漲價時，有現成的備援
- 用官方 SDK 可以使用各家的完整功能，不受第三方抽象層的支援進度限制

### 負面 / 風險

- 自有介面要能涵蓋工具呼叫、串流、結構化輸出等能力，各家的差異要自己處理
- 要維護三家 SDK 的 adapter 與版本更新
- 換模型後，prompt 與輸出品質要重新驗證
- 要簽三家供應商的 DPA，每家的資料保留期間不同
