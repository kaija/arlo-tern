# ADR-0003：一般帳號與群組預設讀取，其他官方帳號由用戶 opt-in

- 狀態：已接受
- 日期：2026-11-13
- 相關：ADR-0001、ADR-0009、ADR-0022

## 背景

連結 LINE 後，讀取服務技術上收得到用戶所有對話的訊息。對話裡的其他人並沒有同意被讀取，讀取範圍越大，處理的第三方個資越多。另一方面，詐騙訊息多半來自陌生人的新對話，task 也常出現在群組，範圍太小會讓核心功能失效。

LINE 的對話有三類：與一般帳號的一對一、群組（含多人聊天室）、與官方帳號（OA）的對話。OA 對話多為行銷與通知訊息，量大、雜訊多。

## 考慮過的選項

1. **全部讀，可排除**：預設讀取所有一對一與群組，用戶可以把特定對話加入排除清單。
2. **用戶勾選才讀**：預設不讀任何對話。最符合資料最小化，但陌生人的新對話不在清單內，可疑訊息警告幾乎失效。
3. **一對一全讀，群組勾選**：保住一對一的詐騙偵測，降低群組的第三方暴露，但群組裡的 task 與群組詐騙預設抓不到。

## 決定

依對話類型分開處理。這是用戶自己提出的做法，介於選項之間；對齊過程中建議的是選項 1（含官方帳號在內全部預設讀取，可排除）。

- **一般帳號的一對一對話與群組**：預設讀取。
- **其他官方帳號（OA）的對話**：預設不讀取。用戶可以在 App 逐一 opt-in 想讓系統讀取的 OA。
- 用戶可以把個別的一般對話或群組加入排除清單（預設假設，對齊時沒有逐項確認）。
- 被排除或未 opt-in 的對話，訊息在讀取服務收到時就丟棄，不寫入資料庫、不送 LLM。
- 本產品自己的官方帳號是 agent 的對話通道，走 Messaging API webhook（見 ADR-0011），不經過讀取服務；讀取服務應略過用戶與本產品 OA 的對話，避免重複處理。

## 後果

### 正面

- 陌生人的新對話與群組都在預設範圍內，詐騙偵測與 task 抽取能涵蓋主要情境。
- 預設排除 OA 可以去掉大量行銷訊息，降低 LLM 成本與誤判。
- 用戶對讀取範圍有控制權。

### 負面與接受的風險

- 預設會處理大量沒有同意的第三方個資，法律依據需要在 DPIA 與合法利益評估中交代（見 ADR-0022）。
- 假冒官方帳號的詐騙（例如假客服、假物流的 OA）預設偵測不到，除非用戶 opt-in 該 OA。
- 來自 OA 的繳費通知、訂位確認等預設不會變成 task。
- 需要可靠地分辨對話類型。linejs 回傳的對話與聯絡人型別是否足以區分一般帳號與 OA，要在實作時確認。
