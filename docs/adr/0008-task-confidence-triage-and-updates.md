# ADR-0008：Task 依信心分流，後續變更由 AI 提出並依信心分流

- 狀態：已接受
- 日期：2026-11-13
- 相關：ADR-0004、ADR-0007、ADR-0010

## 背景

AI 從對話抽出的 task 不一定正確。產品已決定 task 依信心分數分流到行事曆或待確認清單，而且行事曆不與外部行事曆同步。

對話後續常會改期或取消（「改成週五」「那天不約了」）。已經產生的 task 遇到後續訊息時要怎麼處理，需要另外決定。

## 考慮過的選項

後續變更的處理：

1. **AI 提出變更，依信心分流**：管線輸出新增、修改、取消操作，高信心直接套用，低信心進待確認清單。
2. **所有變更都要用戶確認**：最安全，但改期很常見，沒確認前行事曆是舊的、提醒會在錯的時間發。
3. **只新增，不處理變更**：實作最少，但改期會產生重複 task，舊 task 繼續提醒。

## 決定

### 信心分流（既定）

- 管線輸出的每個 task 操作都帶信心分數（0 到 1）。
- 分數達到門檻的直接生效，顯示在行事曆；低於門檻的進「待確認清單」，由用戶接受、修改或拒絕。
- 門檻初始值為 0.8，做成設定，用 eval 集與內測回饋校準（初始值是預設假設）。
- 行事曆是 App 內建的日、週、月檢視，不與 Google Calendar 等外部行事曆同步。

### 後續變更

採用選項 1。

- 管線處理一個對話視窗時，會帶入該對話既有的未完成 task（見 ADR-0007），由 LLM 輸出三種操作：**新增**、**修改**（指定既有 task）、**取消**（指定既有 task）。
- 修改與取消沿用同一個信心門檻：達到門檻的直接套用到行事曆；未達門檻的成為待確認的變更建議，原 task 在用戶確認前維持不變。
- 每次 AI 套用的變更都留下變更紀錄（變更前後的值、時間、來源對話），用戶可以在 App 查看並一鍵還原。
- **用戶手動建立或手動修改過的 task，AI 不再自動覆蓋**。之後的修改與取消一律成為待確認的建議。
- agent 依用戶指示做的修改視同用戶手動修改。
- task 的時間被修改時，重新產生它的提醒（見 ADR-0010）。

### 資料欄位原則

- task 只存 AI 整理過的欄位：標題、日期與時間、是否整天、分類、信心分數、狀態、來源（管線、用戶、agent）。
- 可帶一個指向來源訊息的參照；來源訊息到期刪除後參照為空（見 ADR-0004）。不複製原文片段。

## 後果

### 正面

- 改期與取消能自動反映到行事曆，提醒不會在錯的時間發出。
- 不會因為改期而產生重複的 task。
- 用戶親手改過的內容不會被 AI 蓋掉。

### 負面與接受的風險

- 高信心的誤判會直接改動或取消行事曆上的項目。變更紀錄與還原是補救手段，但用戶可能來不及發現。
- task 只能對應到同一個對話內的後續訊息。跨對話的變更（在群組約好、私訊改期）不會被關聯，會產生新的 task。
- LLM 回報的信心分數不一定校準良好，門檻需要靠 eval 與內測資料調整。
- 「取消」是高風險操作，可以考慮對取消設更高的門檻，這點沒有在對齊時決定。
