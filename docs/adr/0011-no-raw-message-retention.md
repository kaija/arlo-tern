# 0011. 不保存原始訊息內容

- 狀態：已接受
- 日期：2026-11-07

## 背景與問題

系統會讀到用戶的 email 與 LINE / WhatsApp 對話，內容高度敏感。保存原文會增加外洩風險，也會讓 Gmail 受限 scope 的審查（[0008](0008-gmail-access.md)）更困難。

## 考慮的選項

1. 不保存原文，只保留抽取結果
2. 加密保存 N 天
3. 加密長期保存

## 決策

- 原始訊息只在處理管線中**短暫**存在（Pub/Sub 佇列、處理 worker 的記憶體），處理完即丟棄。在 Pub/Sub 中最多保留 24 小時（見 [0027](0027-pubsub-topology.md)）
- 資料庫只保存**抽取結果**：task、可疑訊息警告，以及指回原訊息的**來源參照 ID**（例如 Gmail message ID）
- 適用來源：Gmail、LINE、WhatsApp
- 不適用於用戶與 agent 的對話紀錄：那是用戶直接對 agent 說的話，依 [0014](0014-personal-agent-shared-memory.md) 保存

## 後果

### 正面

- 降低資料外洩的影響範圍
- 有助於通過 Google 受限 scope 的安全審查

### 負面 / 風險

- AI agent 無法搜尋或回顧過去的原始訊息
- 抽取邏輯改進後，無法對舊訊息重新抽取
- Pub/Sub 的保留時間、重送與 dead-letter 設定必須配合，避免原文在佇列中停留過久
- 記錄（log）與錯誤回報不能夾帶訊息內容，需在程式碼與設定層面把關

## 待決

- 警告與 task 中可保留的原文摘錄長度（若有）
