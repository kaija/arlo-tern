# ADR-0005：儲存安全等級——只用磁碟加密，LINE 憑證明文存資料庫

- 狀態：已接受
- 日期：2026-11-13
- 相關：ADR-0001、ADR-0004、ADR-0020、ADR-0021、ADR-0022

## 背景

資料庫保存兩類高敏感資料：

- **原始訊息內文**：最長保存 90 天，含有沒有同意的第三方內容。
- **LINE 登入憑證**：auth token 與端對端加密金鑰。拿到它就能以用戶身分讀取訊息，技術上也能發訊。

需要決定這兩類資料在儲存層的保護等級。

## 考慮過的選項

訊息內文：

1. **每用戶一把金鑰的應用層 envelope 加密**：刪帳號時銷毀金鑰即可讓備份中的訊息一併失效，資料庫外洩也讀不到內文。內文無法直接做資料庫內的全文檢索。
2. **只用資料庫磁碟加密**：實作最簡單、可直接全文檢索。任何拿到資料庫連線的人都看得到明文。
3. **用戶端持有金鑰**：伺服器只存密文，隱私最強，但後端無法在背景處理訊息，與核心需求衝突。

LINE 憑證：

1. **應用層加密後存資料庫**，主金鑰只注入讀取服務。
2. **明文存資料庫**，只靠磁碟加密。
3. **存在讀取服務的本機檔案**（linejs 內建的 `FileStorage`）。

## 決定

- 訊息內文採用選項 2：**只用磁碟加密**（at-rest）與傳輸加密（TLS）。
- LINE 憑證採用選項 2：**明文存 PostgreSQL**，與訊息內文同等級。

這兩項都不是對齊過程中建議的選項。建議的是訊息內文用每用戶金鑰加密、憑證用應用層加密。對齊時沒有記錄選擇這兩項的理由；可以確定的效果是實作最簡單，而且訊息內文可以直接在資料庫內做關鍵字檢索（見 ADR-0015）。

## 後果

### 正面

- 實作與除錯最簡單，沒有金鑰管理的工作。
- 訊息內文可以直接在 PostgreSQL 內建索引與檢索。

### 負面與接受的風險

- 任何能讀資料庫的人或程式（內部人員、SQL injection、外洩的連線字串、外流的備份）都能讀到所有用戶的對話明文。
- 資料庫一旦被讀取，所有已連結用戶的 LINE 帳號都可能被冒用，包含以用戶名義發訊。這是本系統單一最大的安全風險。
- 刪除不是立即完成的：已刪除的訊息與憑證在備份過期前仍以明文存在於備份中。
- 核心服務與讀取服務共用資料庫，核心服務被攻破也等於憑證外洩。

### 建議的緩解（不改變本決定，是否採用於實作時決定）

- 資料庫不對外網開放，只接受同一台主機內部網路的連線。
- 資料庫備份加密，並限制可存取備份的人員與角色。
- 用不同的資料庫角色隔離：憑證資料表只授權給讀取服務使用的角色，核心服務的角色讀不到。
- 用戶中斷連結時立即刪除憑證，並呼叫 LINE 登出該連結裝置，讓外流的舊憑證失效。
