# ADR-0015：Agent 以關鍵字加條件篩選檢索歷史訊息

- 狀態：已接受
- 日期：2026-11-13
- 相關：ADR-0004、ADR-0005、ADR-0013、ADR-0020

## 背景

系統保存原始訊息（最長 90 天，見 ADR-0004）的目的，是讓 agent 可以回答「小明上週說的餐廳是哪間」這類問題。需要決定 agent 用什麼方式檢索這些訊息。

訊息內文以明文存在 PostgreSQL（見 ADR-0005），可以直接在資料庫內建立索引。

## 考慮過的選項

1. **關鍵字加條件篩選**：依對話、發話者、時間範圍篩選，加上資料庫內的中文關鍵字比對。
2. **語意向量檢索**：用詞不同也找得到，但 Anthropic 沒有 embedding API，要再加一家 embedding 供應商，所有訊息都要送出去，到期刪除也要同步刪向量。
3. **關鍵字與向量混合**：效果最好，但同時承擔兩者的成本，對內測偏重。

## 決定

採用選項 1。

- agent 有一個歷史訊息檢索工具（見 ADR-0013），參數包含：
  - 關鍵字（可多個）；
  - 對話或聯絡人（以名稱比對，由伺服器解析成對話）；
  - 時間範圍；
  - 回傳筆數上限。
- 另提供輔助工具：列出用戶的對話清單（名稱、類型、最近活動時間），讓 agent 能先確定要查哪個對話。
- 每筆命中的結果附帶前後若干則訊息作為上下文，並帶對話名稱、發話者、時間。
- 中文關鍵字比對用 PostgreSQL 的索引擴充套件實作。中文沒有空白分詞，而且常見詞多為兩個字，三字組（trigram）索引對兩字詞的效果有限，傾向使用二字組（bigram）索引；具體選用 `pg_bigm` 或 `pg_trgm`，在實作時以實際查詢效果與部署環境的可用性決定。
- 檢索範圍由伺服器端依已驗證的用戶身分限定，只能查到該用戶自己的訊息；被排除與未 opt-in 的對話本來就沒有入庫（見 ADR-0003）。
- 檢索結果有筆數與總長度上限，避免一次把大量原文塞進模型上下文。
- 檢索結果是不可信的內容，以資料的形式提供給模型（見 ADR-0013 的風險說明）。

## 後果

### 正面

- 不需要 embedding，訊息不會再送給第三家供應商。
- 保存期到期時只要刪除訊息資料列，索引自動跟著更新，沒有第二份資料要同步。
- 條件篩選（誰、什麼時候）對這類問題很有效，agent 可以自己換關鍵字多查幾次。

### 負面與接受的風險

- 用詞不同就找不到（問「吃飯的地方」但原文寫「燒肉店」），要靠 agent 多試幾個關鍵字，會增加工具呼叫次數與回應時間。
- 檢索到的原文會進入 agent 的對話紀錄，並送到 Anthropic 處理。對話紀錄的保存期見 ADR-0014 的待決事項。
- 只能查到保存期內、連結之後的訊息（見 ADR-0001、ADR-0004）。
- 圖片與語音訊息沒有內容可查（見 ADR-0001）。

## 之後可以加強的方向

若內測顯示關鍵字檢索的命中率不足，再開新的 ADR 評估加入向量檢索。
