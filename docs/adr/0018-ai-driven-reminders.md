# 0018. 到期提醒：AI 依緊急度決定提前時間，用戶可修改

- 狀態：已接受
- 日期：2026-11-07（2026-11-11 更新）

## 背景與問題

App 要在任務到期前通知用戶。不同任務需要不同的提前量，例如繳費要提前幾天，會議只要提前一小時。需求是由 AI 依任務緊急度決定提前多久。

## 考慮的選項

提醒的控制權：

1. AI 設定，用戶可修改
2. 完全由 AI 決定

task 時間變動時，用戶改過的提醒怎麼處理：

1. 維持提前量，跟著平移
2. 維持絕對時間不動
3. 全部重算並通知用戶

## 決策

- 建立 task 時，AI 依緊急度為它產生**一個或多個**提醒時間（例如 1 天前 + 1 小時前）
- 用戶可在 App 內修改或關閉任一提醒
- **task 時間變動時**：該 task 的**所有**提醒都由 AI 重新計算，包括用戶改過的，並通知用戶提醒已變更
- **排程以資料庫為準**：提醒時間存在 Postgres。Cloud Scheduler 每分鐘呼叫 Core API，由 Core API 找出到期的提醒並發送。改時間只要更新一筆資料，不需取消或重建排程
- 推播透過 Expo Push Service 發送（見 [0020](0020-react-native-expo.md)）
- 提醒決策的 LLM 呼叫走 [0013](0013-llm-provider-abstraction.md) 的抽象層

## 後果

### 正面

- 預設行為貼近任務性質，用戶不必每次設定
- 用戶仍保有修改權
- task 改時間後，提醒一定和新時間一致；用戶會被告知變更

### 負面 / 風險

- AI 判斷錯誤時可能太晚提醒。重要任務的錯誤成本高
- 用戶手動設定的提醒，在 task 改時間後會被覆蓋，需要重新設定
- 以分鐘為單位掃描，提醒最多會晚約一分鐘
- 掃描必須可以重複執行而不重複發送（例如標記已發送），避免同一個提醒發兩次
