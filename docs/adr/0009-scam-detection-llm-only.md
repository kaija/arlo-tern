# ADR-0009：可疑訊息以純 LLM 判定

- 狀態：已接受
- 日期：2026-11-13
- 相關：ADR-0003、ADR-0006、ADR-0007、ADR-0018

## 背景

讀取服務讀到可疑訊息時，要透過 App push notification 警告用戶。詐騙偵測以台灣常見手法為準。需要決定判定的方式。

## 考慮過的選項

1. **LLM 判定加外部訊號**：LLM 依手法分類判定，再用規則補強（網址比對公開的詐騙網站清單、陌生聯絡人與新加入群組加權）。準確度最好，但要維護清單更新。
2. **純 LLM 判定**：只靠 prompt 內的詐騙手法說明。最快做出來，沒有外部資料依賴。
3. **規則與黑名單為主**：成本最低、可解釋，但對話式的詐騙幾乎抓不到。

## 決定

採用選項 2：**純 LLM 判定**。這不是對齊過程中建議的選項（建議的是選項 1）。對齊時沒有記錄選擇的理由；可以確定的效果是最快上線、沒有外部資料依賴。

- 判定在訊息管線的同一次呼叫內完成（見 ADR-0007），模型為 Claude Haiku 5.5（見 ADR-0006）。
- prompt 內列出台灣常見的詐騙手法分類與特徵，至少包含：假投資（投資群組、老師帶單）、假交友與感情詐騙、解除分期付款、猜猜我是誰、假冒公務機關、假冒親友借錢、假網拍與假買家、釣魚連結與假簡訊、假中獎。分類清單放在可獨立更新的設定檔，更新不需要改程式。
- 模型可以使用管線提供的對話中繼資料（對話類型、對方是否為新聯絡人），這些是系統自己的資料，不算外部訊號。
- 輸出：是否可疑、手法分類、信心分數、給用戶看的一句理由。
- 通知分級（初始設計，門檻做成設定）：
  - 高信心：發 App push 警告，並在 App 內標示該對話。
  - 中信心：只在 App 內標示，不推播。
  - 低信心：不顯示。
- 同一個對話在短時間內只推播一次，避免連續洗版。
- 推播的 payload 只放概述（例如「某個對話出現可疑訊息」），不放訊息原文；細節進 App 後才載入（見 ADR-0018）。
- 用戶可以對警告回報「這不是詐騙」，回報用來擴充 eval 集。

## 後果

### 正面

- 沒有外部資料依賴，最快上線。
- 能判斷對話式、沒有明顯關鍵字的詐騙。

### 負面與接受的風險

- 新型手法與新的詐騙網域只能靠更新 prompt 跟上，沒有即時的外部訊號。
- 誤報會讓用戶對警告麻木，漏報則直接是產品失職。兩者的比例只能靠 eval 集與用戶回報衡量。
- 判定用的是 Haiku，判斷力低於較大的模型（見 ADR-0006）。
- 其他官方帳號的對話預設不讀取（見 ADR-0003），假冒官方帳號的詐騙預設偵測不到。
- 詐騙者可以在訊息內夾帶針對模型的指令，誘導模型判定為正常。
- 警告延遲受短視窗合併影響，一般在一分鐘內（見 ADR-0007）。

## 之後可以加強的方向

需要時再開新的 ADR：加入網址信譽比對、對高風險判定用較大的模型複核。
