# ADR-0014：Agent 長期記憶採用明確的記憶條目

- 狀態：已接受
- 日期：2026-11-13
- 相關：ADR-0004、ADR-0013、ADR-0022

## 背景

需求要求 agent「記得我說過的事」。用戶可以從 App、LINE 官方帳號、WhatsApp 官方帳號三個通道跟 agent 對話，記憶應該跨通道、跨對話一致。記憶屬於個人資料，用戶依 GDPR 有查閱與刪除的權利。

## 考慮過的選項

1. **明確的記憶條目**：agent 用工具把值得記的事實寫成短條目，用戶看得到也改得了。
2. **對話全文向量檢索**：不會漏記，但用戶看不到 agent 記了什麼，會撈到過時或矛盾的內容，還要維護 embedding 管線。
3. **只保留對話紀錄**：最簡單，但換一個新對話就忘了。

## 決定

採用選項 1。

### 長期記憶

- 記憶是一筆筆短條目（例如「不吃牛」「偏好靠窗座位」「小孩五歲」），存在 PostgreSQL，每筆記錄內容、建立與更新時間、來源通道。
- agent 透過工具新增、修改、刪除記憶條目（見 ADR-0013）。system prompt 指示它在用戶表達持久的偏好或事實時記下來，一次性的資訊不記。
- 每次對話開始時，把該用戶的全部記憶條目載入 agent 的上下文。條目數量設上限；達到上限時，agent 要先整併或刪除舊條目才能新增。上限的數值於實作時決定。
- **App、LINE 官方帳號、WhatsApp 官方帳號三個通道共用同一份記憶**（WhatsApp 通道見 ADR-0024）。
- 用戶可以在 App 的記憶頁面查看、修改、刪除每一條記憶。
- 記憶只來自 agent 對話。訊息管線不會從用戶的 LINE 對話自動產生記憶。

### 短期脈絡

- 每個通道各自保留近期的對話紀錄作為短期脈絡，存在 PostgreSQL。
- 對話過長時，較舊的輪次以摘要取代。具體做法要等 ADR-0013 的前置驗證第 8 項確認，因為改寫對話歷史可能與 Claude Opus 5.5 的 thinking 區塊規則衝突。
- OA 通道發起、在 App 完成的長任務（見 ADR-0011）會出現在 App 的對話紀錄中。

## 後果

### 正面

- 透明、可控：用戶看得到也改得了 agent 記住的每一件事，符合查閱與刪除權。
- 不需要 embedding 與向量索引，不增加委外處理者。
- 三個通道共用同一份記憶，agent 記得的事不因通道而不同。

### 負面與接受的風險

- 記不記由模型判斷，會有該記沒記、不該記卻記了的情況。
- 全部載入的做法在條目多時會占用上下文，因此需要上限與整併。
- 記憶條目可能含有第三方資訊（例如「媽媽對花生過敏」）。
- 用戶可能在對話中說出敏感資訊（健康、財務），被記成條目長期保存。記憶頁面的可見與可刪是主要的緩解。

## 待決事項

- agent 對話紀錄（短期脈絡）的保存期限沒有在這次對齊中決定。它可能含有 agent 從歷史訊息檢索到的原文，建議比照原始訊息的保存期（見 ADR-0004）或更短。
