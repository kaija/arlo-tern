# ADR-0010：到期提醒由 AI 定時間，系統設護欄

- 狀態：已接受
- 日期：2026-11-13
- 相關：ADR-0007、ADR-0008、ADR-0016、ADR-0018、ADR-0020

## 背景

App 要在 task 到期前通知用戶，提前多久由 AI 依任務的緊急度決定，例如繳費提前幾天、開會提前一小時。需要決定提醒時間具體怎麼產生，以及系統要不要限制 AI 的輸出。

## 考慮過的選項

1. **AI 定時間，系統設護欄**：AI 輸出具體的提醒時間點，系統套用限制。
2. **AI 分類，規則表定時間**：行為可預測、好測試，但對照表沒涵蓋的情境就不貼切，也算不上 AI 決定。
3. **完全由 AI 決定**：實作最少，但可能出現半夜提醒、已過期的提醒時間、提醒過多。

## 決定

採用選項 1。

- 管線抽取 task 時（見 ADR-0007），同時輸出任務類型與一到數個提醒時間點。例如繳費：到期前三天與當天早上；開會：開始前一小時。
- agent 或用戶手動建立 task 時，同樣由 AI 產生提醒時間；用戶可以略過改成自己設定。
- 每個提醒存成一筆提醒紀錄，並排入對應時間的延遲工作（見 ADR-0020）。
- 系統護欄在寫入前套用（數值為初始值，做成設定）：
  - 提醒時間不得早於現在；已經過去的時間點直接丟棄。
  - 提醒時間不得晚於 task 的到期時間。
  - 每個 task 最多 3 個提醒。
  - 勿擾時段為用戶時區的 22:00 到 08:00。落在勿擾時段的提醒提前到勿擾時段開始之前（22:00 前）。
  - 提前後的時間若已經過去，而現在不在勿擾時段，就立即發送一次。
  - 提前後的時間若已經過去，而現在正在勿擾時段內：task 的到期時間在勿擾時段結束之後的，延到勿擾時段結束（08:00）發送；到期時間就在本次勿擾時段之內的（例如清晨 06:00 的班機），**例外允許在勿擾時段內發送**，因為延後就等於沒提醒。這是勿擾時段唯一的例外。
  - task 的到期時間距離現在太近、所有提醒點都已過去時，依上面兩條規則發送一次提醒。
- 用戶可以在 App 修改或關閉單一提醒，也可以調整自己的勿擾時段。
- task 的時間被修改時（見 ADR-0008），刪除尚未發出的舊提醒並重新產生；用戶手動調整過的提醒不重新產生，只依相同的提前量平移。
- task 被取消或完成時，取消它尚未發出的提醒。
- 提醒透過 App push 發送（見 ADR-0018）。發送當下再檢查一次 task 的狀態，避免對已取消的 task 發提醒。
- 預設時區為 Asia/Taipei，以用戶裝置回報的時區為準。

## 後果

### 正面

- 提前量貼合任務性質，符合「AI 依緊急度決定」的需求。
- 不會出現半夜推播、過期提醒或同一件事提醒過多。
- 用戶保有最終控制權。

### 負面與接受的風險

- AI 選的提前量不一定符合個人習慣，初期要靠用戶手動調整。調整紀錄目前不會回饋給 AI。
- 護欄的規則會覆蓋 AI 的決定，兩者的互動（例如清晨的會議）需要針對邊界情況寫測試。
- 旅遊行程的逐項提醒規則沒有在這次對齊中決定，見 ADR-0016 的待決事項。
